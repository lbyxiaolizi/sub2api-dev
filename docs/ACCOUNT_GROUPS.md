# 账号组

账号组是现有「分组」之下的配置管理功能，不替代原有的账号与分组绑定。

## 使用

1. 在管理后台进入「账号组」（也可从「账号管理」顶部进入）。
2. 创建账号组：选择所属分组、成员账号，以及初始配置来源账号。
3. 保存后，来源账号的共享配置会同步至所有成员。
4. 列表中的「编辑」调整名称和成员；「账号设置」打开与该平台、认证类型对应的完整设置表单（模型映射、协议、配额、调度、指纹等），与单账号设置使用同一组件。创建后会自动打开账号设置。
5. 账号列表显示所属账号组，点击成员的编辑按钮会进入账号组配置。

成员必须已绑定到账号组的所属分组，且平台和认证类型相同。一个账号只属于一个账号组。影子账号保持独立管理。

## 一键新建同组账号

API Key 和上游账号组的列表操作中提供「新建同组账号」。弹窗只需填写：

- **API 地址**：默认使用账号组当前配置中的地址（创建组时来自所选来源账号，也支持多协议/平台默认地址）。保持不变或留空时继承组地址。
- **API Key**：仅保存到新账号，其他成员的密钥不变。

账号名称自动生成，分组、平台、类型、模型映射、配额、代理、调度等设置从账号组继承。创建账号、绑定分组和加入账号组在同一事务内完成；失败不会留下未归组账号。

手动填写不同的 API 地址后，该地址作为新成员的独立地址保留，后续组设置同步不覆盖它，也不修改组默认地址。多协议请求仍按组协议规则选路，但使用该成员的独立上游。移出/解散后保留最后使用的地址，恢复普通账号编辑。

OAuth、服务账号和 Bedrock 等凭证类型继续使用各自的认证创建流程。

## 配置与身份

共享配置包含备注、代理或代理池、并发数、优先级、计费倍率、负载因子、启停、调度开关、过期策略，以及模型映射、请求头、配额限制、平台请求选项等受支持的平台配置。

账号名称、API Key、OAuth Token、服务账号身份、用量、限流、故障和探测结果等身份或运行状态仍按账号独立保存。Ollama/OpenCode 的会话及用量采集生命周期沿用供应商凭证身份维度管理。共享配置中的代理池统一设置池绑定，池内实际代理分配仍由代理池维护。

管理 API 的高级配置示例（界面中可使用对应的表单控件）：

```json
{
  "credentials": {
    "base_url": "https://api.example.com/v1",
    "model_mapping": { "model-a": "upstream-model-a" }
  },
  "extra": {
    "quota_daily_limit": 20,
    "quota_weekly_limit": 100
  }
}
```

`credentials`、`extra` 每次提交会替换相应的组配置对象；省略某个键会取消该键的共享设置。身份及运行态键不会被复制，未知键会被校验拒绝。手工选择 OpenAI 订阅档位时组内统一应用；选择自动识别后，各成员恢复自己的实际订阅档位。关闭独立的上游计费倍率自动同步后再加入账号组，以免两种倍率管理方式冲突。

## 成员与删除

- 新成员使用账号组配置。如果会删除或改变新成员已有的普通／Compact 模型映射，操作先返回冲突且不写入；界面提示核对配置来源或账号组映射，只有明确确认覆盖后才继续。
- 移出成员保留最后一次配置，恢复独立编辑。
- 解散账号组不删除成员账号，也不回滚配置。
- 删除账号会移除成员关系；删除所属分组会解散其账号组。
- 成员仍在组内时，应先将其移出账号组，再解除所属分组绑定。

同步与成员变更在同一数据库事务中完成。数据库唯一约束阻止并发重复归组；外键约束保证成员保留所属分组绑定。调度缓存同步更新，后台凭证刷新也会保留最新的组配置。

## 管理 API

均位于 `/api/v1/admin/account-groups`，沿用管理员认证和审计中间件。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/` | 列表，可通过 `group_id` 筛选所属分组 |
| POST | `/:id/accounts` | 新建同组账号：`api_key`、可选 `base_url`；支持 `Idempotency-Key` 重试 |
| POST | `/` | 创建：`name`、`group_id`、`account_ids`、可选 `source_account_id` |
| GET | `/:id` | 读取成员及配置 |
| PUT | `/:id` | 更新：可选 `name`、`account_ids`、`config` |
| DELETE | `/:id` | 解散 |

创建／成员更新可使用一次性的 `confirm_model_mapping_overwrite: true` 确认模型映射覆盖，默认遇到映射减少或目标改变时返回 `ACCOUNT_CONFIG_GROUP_MAPPING_CONFLICT`，不做自动合并。

`config` 支持按顶层字段部分更新；数值 `0` 和布尔值 `false` 会生效。可空字段可使用 `null` 清除，例如 `proxy_id`、`pool_id`、`expires_at`、`load_factor`。直接修改受管成员的共享配置会返回 `ACCOUNT_CONFIG_GROUP_MANAGED`。

数据库迁移：`backend/migrations/241_account_config_groups.sql`，通过现有启动迁移机制应用。
